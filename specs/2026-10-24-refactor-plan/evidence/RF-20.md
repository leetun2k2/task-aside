# RF-20 — Isolate message sends and deduplication

## Outcome
- In-flight message sending is strictly bound to its captured `targetTaskId` parameter rather than whatever task is currently selected when the asynchronous write finishes.
- Migrated global sending flag to `sendingTaskIds: Set<string>` to track pending send operations per target task without blocking input or navigation on other tasks.
- Reconciled REST and SSE message completions by ID: incoming messages are deduplicated so that racing between REST completion and SSE `message.completed` events will not create duplicate entries in the conversation.
- Preserved user draft content in the textarea upon send failure or task status changes (e.g. entering `processing` or `hitl`), clearing composer text only upon verified send success or explicit task navigation.
