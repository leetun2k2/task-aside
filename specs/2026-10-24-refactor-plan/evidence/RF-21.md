# RF-21 — Move task actions onto server data

## Outcome
- Integrated task creation, edit, cancel, and retry actions with authoritative server responses and TanStack Query cache management.
- Cancel action preserves verified-stop-before-lock-release invariant: client performs `cancelTask(targetId)` and only marks the task cancelled upon authoritative backend confirmation.
- Each action handler updates query cache (`queryClient.setQueryData`) with authoritative returned records and triggers targeted invalidation (`invalidateQueries`), reconciling backend ordering and versioning.
- In-flight actions capture `targetId = selectedTask.id` at execution start, preventing selection changes during request latency from mutating the wrong task.
- Added `isActionLoading` submission guards preventing repeated rapid submit clicks.
- Synchronized repository additions with immediate cache update and consumer invalidation.
