# RF-17 — Support cancellation and validated reads

## Outcome
- Added `MalformedResponseError` extending `ApiError` with HTTP status `502` and code `MALFORMED_RESPONSE`.
- AbortSignal is explicitly passed through read options into native `fetch`. When an `AbortError` occurs, it is rethrown without wrapping in a generic 500 error, allowing caller abort handlers to detect request cancellation.
- All frontend read boundaries (`fetchTasks`, `fetchTaskById`, `fetchRepositories`, `fetchMessages`, `fetchSettings`) as well as mutation returns validate payload schemas using Zod schemas (`TaskSchema`, `RepositorySchema`, `MessageSchema`, `SettingsResponseSchema`).
- Any schema mismatch or invalid server payload throws `MalformedResponseError` with validation issue details.

## Verification
- `bun run typecheck`: Passed cleanly with zero TypeScript errors.
- `bun run test:ui`: Verified that:
  - Aborting a read using `AbortController.signal` causes immediate `AbortError` rejection.
  - A malformed response payload (e.g., missing mandatory properties or invalid data types) is rejected with `MalformedResponseError` (502 `MALFORMED_RESPONSE`).
- `bun run test:browser`: Headless Chrome CDP tests passed for initial mount, token bootstrap, header binding, and markdown rendering.
- `bun run test:workflow`: Full live user workflow test suite passed.
