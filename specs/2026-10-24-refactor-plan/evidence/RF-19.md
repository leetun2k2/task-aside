# RF-19 — Scope conversation reads by task

## Outcome
- Migrated conversation message loading in `src/frontend/App.tsx` to TanStack Query keyed explicitly by `queryKeys.messages(selectedTaskId ?? '')`.
- Replaced the previous single shared messages state with per-task query caching and `setTaskMessages` scoped updater.
- When the selected task changes, any in-flight conversation read for the previous task is automatically aborted via `AbortSignal`, and the newly selected task's query key takes precedence immediately.
- Prevented cross-task state contamination from delayed or out-of-order network responses.
- Updated `message.completed`, `input_required`, and send message operations to target the authoritative task ID rather than whatever task happens to be currently selected.

## Verification
- `bun run typecheck`: Passed with zero TypeScript errors.
- `bun run test:ui`: Added automated task-scoping anti-race check in `ui-checks.ts`:
  - Simulated a delayed Task A read (50ms) and faster Task B read (10ms).
  - Confirmed Task B's conversation cache strictly contains Task B's messages without pollution from Task A.
  - Verified fast A–B–A navigation restores Task A's conversation cleanly from cache.
- `bun run test:browser`: Verified full headless Chrome CDP browser interaction against Vite SPA with task-scoped conversation reads.
